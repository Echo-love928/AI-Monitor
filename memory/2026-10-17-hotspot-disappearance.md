# DEBUG REPORT — 热点和 B站视频消失

- Status: DONE_WITH_CONCERNS（本地修复完成；新版付费语义评估待额度恢复后运行）
- 日期：2026-10-17
- Symptom：用户反馈严格相关性审核后看不到新热点，原先 B站视频消失。

## Root cause

1. 作者作品误用新闻事件新颖性：鱼皮 10 月 15 日的视频在五天窗口内、直接匹配作者规则，仍因 `isNewEvent=false` 隐藏。已用修复前生产包和数据库原文确定性复现。
2. 历史审核的结构化输出校验失败被迁移为不可见待审。已有直接关联的原文、引用与有效历史结论也受影响；合并指针或事件类型措辞差异会进一步丢弃整条材料。
3. 视频解析阶段按 URL 分开，最终事件标识却遗漏视频地址，同作者同日同类型作品会覆盖。
4. 普通教程标题在全局材料筛选中被过滤，没有考虑用户已明确要求教程。
5. 默认只显示 24 小时，与采集五天窗口不一致。
6. 验收已用满当天 190 次授权额度。最近检查审核 0 条；页面没有充分说明额度阻塞。无模型配置时的提前返回、额度失败批次的中断，还会阻止后续无需语义模型的作者视频收录。
7. 用户当前有 8 条监控，全部暂停；不能自动替用户开启或还原为此前 6 条规则。

## Fix

- `server/relevance.ts`、`shared/relevance.ts`：精确作者作品匹配、视频或编程导航内容的或关系、明确教程范围；审核缓存策略更新，不重复运行旧数据全局隔离迁移。
- `server/ai.ts`：作者新作及明确要求的具体教程按作品发布时间判断；新作品不刷新旧模型发布；错误合并指针从当前原文独立形成事件；最终视频标识包含 URL；作者作品元数据可离线收录，事实仍标待核实。
- `server/quality.ts`：教程价值下放至逐监控审核，来源、时效与原创限制继续执行。
- `server/runner.ts`：配置或额度不可用时先独立处理关注作者作品，其余语义候选保持待审，不消耗重试次数，不发模型请求。
- `shared/feed.ts`、`web/src/App.tsx`：默认五天，展示额度用尽、候选已保存和全部暂停，避免把未完成审核说成内容无关。
- `scripts/recover-visible-signals.ts`：默认离线预览，应用前完整备份，逐条保存修改审计；当前规则、来源、设置、邮件与使用计数受保护。
