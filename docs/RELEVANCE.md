# 逐监控相关性审核

2026-10-17，按人工确认方案实施。

关键词命中需要原文支持的直接关联。模型逐监控输出 `direct / weak / unrelated / insufficient`、匹配理由、该目标的摘要、实体/版本/动作、未满足约束和原文引用。生成契约约束可用编号，服务端再次验证原文片段、精确型号与版本、作者与作品类型及新模型事件依据。仅提品牌、同公司、同生态、配置清单或没有结果的评测介绍不能形成直接匹配。

“相关但事实待核实”与“相关性证据不足”分别处理。前者仍执行原有来源、时效、原创、互动和热点价值限制；后者进入独立待审核列表，有限重试。卡片、详情、关键词筛选、分享及邮件使用对应监控的有效结论，不把宽泛范围命中套给具体型号。不显示相关性百分比分数。

合并重新评估已覆盖规则，允许撤销错误匹配；未覆盖的规则保留审核快照。规则指纹、材料指纹与审核版本使查询变化或正文变化能够重审，指标变化不会撤销原文引用。原文引用还保存内容指纹，正文被替换后旧匹配失效。

查询扩展最多三个目标等价写法，保留实体与版本，未知模型 ID 不自动扩展。搜索在现有限额内轮转，记录原始规则与检索式；纯产品监控不强制附加发布词。较长材料选取目标所在上下文，不只读取开头。扩大召回不放宽审核边界。

审核批次最多八条材料，模型输出预算 32,000 tokens；同一主材料及关联原文保持同批。模型声明支持低推理档位时才发送该参数。每条输入材料在固定编号对象中给出事件或过滤理由，事件必须包含该材料自身的原文引用。先逐材料校验，再合并同一事件；不同视频链接不因作者和日期相同而合并。输出截断、编号错误或审核失败不形成有效热点，保留候选并记录失败。失败不伪装成无关或空结果。

## 自动评估

```powershell
npm run eval:relevance
npm run eval:calibrate -- --live
npm run eval:relevance -- --live --dev
npm run eval:relevance -- --live --holdout
npm run eval:relevance -- --live
npm run eval:relevance -- --live --retry-errors
```

无 `--live` 只检查样本清单。真实运行使用现有 OpenRouter 配置，在生产每日调用限额中预留用量，不访问采集来源、不发送邮件；结果按契约、模型和样本缓存。独立评估模型可由 `EVAL_JUDGE_MODEL` 指定，必须不同于生产模型。默认使用 Qwen 235B，先通过十个独立边界样本的保留/过滤校准。弱相关与无关都过滤，四类标签的细分分歧另外统计。精确版本另用独立字符串校验，保留模型的原始分歧和修正原因；不能让模型把版本号当浮点数。模型、判据、校准样本或版本校验变化都会使校准失效。本机尝试的 OpenAI、Google 评估模型曾返回区域不可用，不修改生产模型或网络配置来绕过限制。

`eval/fixtures/relevance.json` 固定 160 个规则—材料样本：60 个来自冻结真实材料，100 个为明确标识的合成边界材料。第一轮 120 个样本包含 57 个原保留样本，首次保留集未通过，完整失败报告保存在 `reports/relevance-eval/first-holdout-report.json`。这些样本全部转为回归集，另外冻结 40 个未交给生产模型的新保留样本；已看过的材料不会再次冒充未见数据。相同文章及已识别的同一事件分在同一组，回归与保留集不跨组；时间使用固定时钟，未来运行不会因样本自然过期产生假回归。

用户确认的口径统一用于所有同类样本：没有具体结果的评测介绍过滤；编程 Agent 需要明确编程关联；具体编程 Skill 的相关性可直接命中，是否为教程、是否有新事件另行筛选。两条合成视频简介补齐到原有材料长度门槛，未放宽来源门槛；修改过输入的旧视频样本不纳入旧契约缓存对比。

评估运行真实生产审核与服务端校验，而不是用替身返回预期结果。旧版契约在 62 个输入未变的样本上配对比较，失败照实计入。自动报告准确率、候选集召回率、误收/漏收、证据不足比例、样本量和置信区间。独立模型先只看原文盲判等级，再单独审核生成解释是否有原文依据、解释匹配关系、覆盖约束、没有无关填充；等级盲审不接触生产模型的结论和摘要。分歧按相同标准、每批最多八条做一轮盲审复核，保留两轮判定；不循环抽样直到一致。初始分歧与未解决分歧单列，不静默改成一致。

`--retry-errors` 仅对执行、格式、目标摘要缺失或引用校验失败的材料重试，含首次最多三次，与生产候选的重试上限相同；有效的弱相关/无关结论以及真正缺失原文不触发重抽。已完成材料不因同批其他材料失败而重新取样。每次失败缓存和最终报告的 `retryAudit` 都保留。首次新保留集报告另存，重试后的结果不冒充首次成功。修正人工已确认口径下的错误标签时，须保留前后标签、独立判定与原始输入一致证明；只有模型实际输入未变才复用对应缓存。

长文未出现宽泛查询的字面短语时，仍保留完整的 5,000 字上下文预算，避免只读开头 1,200 字而漏掉后面的具体开发任务。长文修复的缓存迁移逐批比较实际输入；独立盲审另按每条原始输入与评估判据缓存。受影响的审核、盲审及历史分组均重新运行，复用清单保存在 `reports/relevance-eval/excerpt-cache-reuse.json`。

已人工确认的评测无结果和编程 Skill 口径保存在 `eval/fixtures/confirmed-policies.json`，绑定查询及完整原文指纹。评估员的相反判断保留在 `rawDisagreements`，按已有人工口径记录 `policyResolutions`；其余未解决分歧仍阻止验收，不把模型原判改写成一致。材料或标签变化后原确认失效。评估脚本、判据或人工记录变化也会使历史应用的验收签名失效。

首版门槛：保留准确率至少 95%，候选集召回率至少 85%，关键误收为零，解释质量至少 95%。零保留、缺少正例或过小样本不判通过。全量/保留集还三次复查“OpenClaw 可命中编程领域、不能命中缺失的 Sonnet 4.6”这一跨监控反例。统计只覆盖冻结候选集，不等同于全网召回率。

报告在 `reports/relevance-eval/`；失败与未完成状态保留。调试集只用于调整，保留集在方案锁定后运行；后续失败案例加入回归。公开采集的查询扩展效果另在相同预算下观察有效新增和噪声，不通过多搜几倍请求宣称审核提高。

临时额外验收额度通过 `EVAL_REQUEST_LIMIT` 指定，最多为日常限额加 90，必须先取得人工授权，不修改日常监控设置。本次经人工分次确认，总上限为 190 次，日常监控仍为 100 次。

## 2026-10-17 可见性与召回修复

关注某位作者的视频时，具体作品的近期发布本身满足新颖性；核对真实视频地址、发布作者、简介和最近五天的发布时间后，可独立收录为待核实线索。仅取得简介不能声称读取过视频或字幕。新上传的旧模型介绍不命中新模型发布规则，正文提及作者也不能冒充本人发布。作者视频与编程导航内容的“或者”按两条可独立满足的范围处理。

明确要求项目教程、教学或课程的监控，允许近期发布且有具体用途的相关教程。普通教程的全局标题过滤移至逐监控价值判断；泛领域监控仍筛选热点价值，准确型号、明确编程关联和原文引用约束继续执行。合并指针实体或版本错误时，从当前材料独立验证并另存事件，不借用错误历史来源；仅事件类型措辞不同不丢弃有效材料。最终视频事件标识包含作品地址，避免同作者同日作品互相覆盖。

额度耗尽或 AI 尚未配置时，作者作品按已取得的发布元数据先行收录；其他规则的语义关联继续待审，不消耗模型调用或候选重试次数。该流程不依赖作品排在第几个审核批次。默认时间范围调整为最近五天，页面明确显示额度用尽和监控暂停状态。

本次 154 项本地回归测试及构建通过，新增测试位于 `tests/hotspot-recovery.test.ts`，待审重试测试位于 `tests/freshness.test.ts`。旧版生产代码与修复前跨批次测试均复现了故障。离线恢复先预览再创建 SQLite 备份，保留每条修改前记录；恢复只使用精确作者元数据、原文未变的有效历史引用，以及逐条复核的 OpenAI 视频简介，不额外调用模型。服务实际验证由 3 条可见内容恢复为 11 条，其中 B站视频 5 条；原有 8 条规则的暂停状态、来源、设置、邮件和全部用量保持不变。仍有 94 条候选等待语义审核，今天 AI 已用 190 次，日常限额仍为 100。

离线恢复工具 `scripts/recover-visible-signals.ts` 默认只读预览；`--apply` 创建完整备份并留存修改审计。过程与限制见 `memory/2026-10-17-hotspot-disappearance.md`。没有重跑付费的 160 样本盲审，不宣称新版获得旧版的准确率指标。
