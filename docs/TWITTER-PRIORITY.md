## 当前规则

- Twitter 优先发现热点，不再设置每轮 X 十条上限。普通回复、纯转发、类型未知内容和空泛讨论过滤；官方或同一原作者的补充只作对应会话的佐证。
- 有具体新增事实的原创不要求外链。互动量只辅助排序；单条普通推文不能直接确认事实，缺佐证时明确标记待核实。
- 网页搜索仅为当前线索定向补证，不再通过泛关键词搜索独立生成热点。官方 RSS/发布页补充重要新模型、新版本或实质进展；普通客户案例、教程、营销不作为热点。
- 默认“近 5 天热点”展示优质 Twitter 待核实线索和已核实新事件；可切换已核实、待核实、全部。低质量、旧闻、被排除项仅进入审计接口。
- 时间窗口固定为滚动 120 小时。事件发生时间优先；时间未知的 Twitter 线索使用最早的有效原创发帖时间。抓取、修改、发现和新转发时间均不能刷新旧事件；缺发布时间的网页或 RSS 不独立发现事件。
- 超过 5 天立即由 API 和前端排除，worker 每分钟更新排除标记。采集、选择、重新核实和邮件资格均检查窗口；整段过期的 X 检查点直接放弃。原始记录及历史审计快照保留。新推文引用的旧原文可保留为识别旧闻的上下文，不能单独入选或确认近期事实。
- AI 必须分别判断 `isNewsworthy` 和 `isNewEvent`。单条实体、版本或类型合并冲突隔离，该条保留重试资格；同批其他有效结果继续保存。虚构编号、覆盖不全等全局错误继续拒绝整批。

## 实现与迁移

`shared/freshness.ts` 统一前后端时间规则，`server/retention.ts` 负责无删除的过期标记。`quality.ts` 区分发现资格与补证材料；`runner.ts` 优先 X 并按需调用网页来源；`ai.ts` 分离新颖性、选题价值与事实核验。

质量版本更新为 2。迁移保留全部候选与事件，将旧事件另存 `event-audit-v2`，合格候选重新开放审核；旧版未经新颖性筛选的事件先进入审计，复核后才重新展示。设置固定为 120 小时，API 拒绝其他窗口值。

迁移前在线备份：`reports/backups/before-twitter-priority-2026-10-16.sqlite`。迁移时保留 372 条候选、33 个原有事件与 33 份新审计快照。
