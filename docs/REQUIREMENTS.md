# AI Monitor 需求文档

版本：0.3。更新日期：2026-10-13（Asia/Shanghai）。状态：方案已获用户确认，网页版开发与真实联调进行中，待用户验收。

本稿按用户最新补充整理，覆盖此前的检查频率、暗色界面和默认依赖 OpenRouter 联网搜索的建议。实现细节见 PLAN.md，接口核对记录见 API-RESEARCH.md。

## 1. 产品目标

为 AI 编程博主自动发现大模型更新、AI 编程工具和相关领域的新热点，减少人工搜索，提供可追溯的信息与及时邮件通知。首版是轻量个人工具，先本地运行和验收，再决定部署。

产品交付分两阶段：先完成响应式网页版并通过验收，再封装 Agent Skills，供其他 AI 调用监控与热点发现能力。

## 3. 功能需求

### R01 关键词与目标监控

支持输入关键词或自然语言目标，例如“某个模型的新版本正式发布”。支持新增、编辑、暂停、恢复和删除。系统通过多个信息源发现候选内容，再使用 AI 判断是否真正发生了用户关注的事件。

正式通知需要同时满足目标相关、新事件、证据充分等条件；匹配到关键词文字本身不等于命中真实事件。

### R02 指定范围的热点发现

支持设置领域范围，例如“AI 编程”“编程 Agent”“开源模型”。每 30 分钟采集并分析，展示标题、中文摘要、关注理由、时间、可信状态、来源和可获得的真实讨论数据。

支持按范围、可信状态和来源筛选，按新鲜程度或关注度查看。没有获取到的互动数据不能编造。

### R03 多源采集

首版来源组成：

1. 网页搜索结果采集：优先验证 Bing 普通搜索页面；DuckDuckGo 非 JavaScript 页面作为待验证备选。
2. X 数据：TwitterAPI.io 最新搜索；可信账号时间线辅助捕获发布信息。
3. 原始发布来源：多个域名的公开 RSS/Atom、官方博客或发布记录。

每轮尝试所有已启用且与规则相关的适配器，不能找到第一条结果就停止其他来源。相同查询和相同公开订阅源跨规则复用采集结果，避免重复请求。

网页展示来源配置状态及本轮运行结果。某一路失败时其余来源继续工作，结果标明“部分来源失败”；全部失败时显示失败，不显示“没有热点”。缺少 TwitterAPI.io Key 时明确显示 X 未配置，不能视为完成多源联调。

“来自多个采集渠道”与“被多个独立原始来源支持”分别统计。同一公告的搜索命中、RSS 条目和转发不算三份独立证据。

### R04 真实性与证据

展示“已核实”“待核实”“已排除”及理由。搜索摘要、搜索引擎生成的 AI 摘要、X 蓝标和点赞数量均不能单独证明内容真实。需要核对原文、最终域名、发布者身份、时间和上下文。

仿冒域名或账号、预测、传闻、旧闻重发、证据冲突及与目标无关的内容，不能产生正式发布通知。待核实内容后续获得有效证据时可升级，并按其是否属于正常监控期决定通知。

### R05 邮件通知

通过 SMTP 向用户配置的邮箱发送通知。邮件包含命中目标、摘要、判定依据、原始链接和发现时间。网页记录待发送、重试、SMTP 已接受和失败状态。

同一目标与同一事件避免重复通知；不同版本发布不能错误合并。提供 SMTP 连接检查和测试邮件，并通过真实收件测试验收。

### R06 后台运行

监控在独立常驻后台进程执行，关闭网页后继续；规则、运行记录和通知状态持久化。服务退出或电脑休眠期间不能监控，恢复后补查近期窗口。

支持“立即检查”，同时遵守采集限速、冷却时间和并发限制；连续点击不能启动重复任务或绕过站点限速。自动检查周期保持 30 分钟。

### R07 配置与运行可见性

提供 OpenRouter、TwitterAPI.io、SMTP 配置状态；领域/账号/公开订阅源管理；模型选择；最近和下次检查时间；各来源运行状态与失败原因；调用限额及可获得的用量。

真实密钥保存在服务端本地环境配置中，不出现在前端响应、日志和示例配置里。缺少密钥时提供配置引导，不展示虚构热点。

### R08 亮色响应式界面

采用明亮底色、深色文字、清晰的状态色和有辨识度的信息结构。手机与桌面都能完成添加监控、筛选热点、查看证据和通知记录；键盘焦点、触摸区域、错误提示和减少动效偏好均可用。

### R09 Agent Skills 第二阶段

网页版验收后，封装技能说明与 CLI/API 调用入口，支持其他 AI 创建/管理监控、执行一次检查、查询热点及查看运行状态。复用网页版的采集、证据、去重与通知逻辑。持续调度由后台或宿主调度能力承担，技能文本本身不承担常驻运行。

## 4. 首版边界

首版不增加多用户体系、大规模分布式采集、复杂管理权限和实时流订阅。TwitterAPI.io 首版采用 30 分钟轮询，不引入 WebSocket/webhook 实时流套餐。

不把 OpenRouter 联网搜索作为网页搜索采集的替代；当前首版默认不启用该插件，也不要求用户运行时依赖 Firecrawl 或 Context7。MCP 用于开发资料核对。

## 5. 验收标准

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| A01 | 规则管理与保存 | 操作生效，重启后数据仍保留 |
| A02 | 30 分钟周期 | 两类任务统一调度，展示下次时间；关闭网页后仍运行 |
| A03 | 多源真实采集 | 后端网页采集、TwitterAPI.io、至少两个域名的公开订阅源均有真实请求记录和可核对结果 |
| A04 | 采集降级 | 单路失败其余继续；全部失败不显示空结果成功；X 未配置状态明确 |
| A05 | 发布时间与增量分页 | X 使用最新排序和有效时间窗口；游标、空页、重叠窗口和延迟索引不会导致静默漏数 |
| A06 | 真伪与误报 | 仿冒、预测、转载、旧闻及证据不足不产生正式发布通知 |
| A07 | 合并与通知 | 同事件转载不重复通知；新版本可区分；待核实升级路径有效 |
| A08 | 真实邮件 | SMTP 连接可验证，实际测试邮件到达用户邮箱 |
| A09 | 异常与限额 | 网页验证码/429、X API 错误、非法 AI 输出、余额不足及 SMTP 失败均可识别并记录 |
| A10 | 页面使用 | 375/768/1440px 可操作，采用亮色，表单与键盘导航无阻塞 |
| A11 | 文档与实现一致 | 关键接口依据 MCP 获取资料，依赖版本锁定，未混用其他 Node/Express 版本的方法 |
| A12 | 阶段顺序 | 用户完成网页版验收确认后，才开始技能封装；技能调用另行验收 |

固定证据与模拟外部服务用于可重复的业务边界测试；真实网络、API 与收件测试单独记录。模拟测试不能替代 A03 和 A08。
